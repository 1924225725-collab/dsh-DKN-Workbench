# dsh-DKN-Workbench

DKN 集成工作台是面向 DeepSeek Harness 的 Windows 插件（原名 DKN Agent）。在 DSH 中浏览和继续本机 Codex 项目对话，使用 Codex、CodeBuddy 和 ZCode 的 CLI 模型，通过 Qoder ACP 使用本机账号模型，并按项目组织 Agent 协作。当前为 `2.1.7`，适配 DSH `0.2.2-rc.1` / `0.2.2-rc.3`。

[下载最新版](https://github.com/1924225725-collab/dsh-DKN-Workbench/releases/latest) · [独立 CodeBuddy 版（国内 CLI）](https://github.com/1924225725-collab/dsh-codebuddy-cli-cn) · [English](README.en.md)

## 安装与入口

### 接入的平台

| 平台 | 模型与对话能力 | 额度与每日奖励 |
| --- | --- | --- |
| CodeBuddy 国内／国际 | 官方 CLI 模型、独立账号池、带账号名称的模型路由 | 官方积分余额；国内版支持手动每日签到 |
| Codex | CLI 模型提供方，以及完整 app-server 原生项目／对话模式 | 读取已连接账号的限额窗口，不提供签到 |
| Qoder | 通过官方 CLI ACP 读取模型目录并在 DSH 对话中使用 | CLI 套餐／加量包额度；Windows 国际版桌面账号支持手动领取每日奖励 |
| ZCode | app-server 模型目录与流式对话，支持 Coding Plan／Start Plan 配置 | 对应通道的额度查询；活动领取尚未开放 |

模型运行依赖本机已安装、已登录的官方 CLI／运行时，不附带第三方平台账号或免费额度。项目协作直接使用 DSH 工作区和已有对话。

1. 从 [GitHub Releases](https://github.com/1924225725-collab/dsh-DKN-Workbench/releases) 下载 `dsh-dkn-agent-2.1.5.tgz`。在 DSH 插件管理中选择本地安装包并启用；已有旧版可更新同名插件。
2. 打开“DKN Agent · Codex”设置入口，按需填写官方 Codex CLI 路径；自动发现正常时留空。进入“模型配置 → Codex CLI”后可检测 CLI 版本、发送测试请求、配置模型清单、默认工作目录、调用超时和默认推理强度。模型配置中还提供 ZCode CLI，填写或自动发现 zcode.cjs 后即可使用 ZCode 已登录账号的动态模型目录。
3. 如果提示侧栏补丁已准备，从应用菜单**完全退出 DSH**，等待约 15 秒再打开。关闭到托盘不会释放归档锁。补丁只支持已核对的 DSH 版本，失败原因显示在设置页。
4. 工作区与 Codex 项目在**同一滚动区域**：向下滚动，经过分界线和 Codex 标题继续浏览。展开项目并打开对话，使用 DSH 原生对话界面继续。
5. 左侧点击 **项目协作**，或从 DKN Agent 首页、总设置进入项目协作。自动读取 DSH 工作区项目，项目中的对话自动成为成员；在 DSH 中管理项目和对话，在成员页配置职责与协作权限。

需要 Windows 10/11、DSH `0.2.2-rc.1` / `0.2.2-rc.3`，构建和 CLI 环境使用 Node.js `24.9+`。需要哪个运行时，请先自行安装并完成其官方登录。插件不代办登录、不复制凭据、不安装 Agent 软件。

## 2.1.5 Qoder 每日奖励查询修复

修复官方 Qoder 可领取、插件却显示没有每日活动的问题。活动接口在缺少官方桌面设备身份时可能返回不完整列表；现在使用本机已安装 Qoder 桌面端的官方身份组件及真实账号／设备信息重新查询，查询和手动领取使用同一身份，不生成替代设备。

支持自动发现注册表记录的自定义安装目录及版本目录；发现失败时，可在 Qoder 基础配置填写“每日奖励：桌面安装路径”。组件或身份不可用时明确提示原因，不再判为无活动。本机修复前后只读对比已确认：旧请求无活动，新请求显示可领取 100 Credits；本轮未执行真实领取。

## 2.1.4 顶部签到状态与一键签到

配置首页、模型配置首页和额度页顶部增加签到状态汇总，分别显示 CodeBuddy 国内、Qoder 国际的当前状态。“一键签到”直接依次检查并领取这两个当前账号的每日奖励，已领取／无活动跳过，单个平台失败不阻塞其他平台，结束后显示处理结果并刷新额度。范围为 CodeBuddy 国内当前默认账号与 Qoder 国际桌面账号；号池其他账号需在各自入口操作。

单个平台配置页的签到状态移到上方，“一键签到”改为单击执行，不再要求第二次确认。不会启动后自动领取，网络异常仍不自动重试。

## 2.1.3 手动签到与每日奖励

CodeBuddy 国内版、Qoder 国际版配置页和额度页新增“每日奖励”。查询状态后可点击“签到领取”，确认后才发送领取请求，完成后刷新状态和额度。CodeBuddy 国内号池的每个账号也有独立入口，不切换其他账号，不自动领取。

Qoder 使用当前 Windows 国际版桌面账号，可能与 CLI 账号不同；需要已安装并登录 Qoder 桌面端。只识别每日 100 Credits 活动，不领取新人、订阅或其他礼包。每天北京时间 10:00 刷新，未下发活动、不符合资格和已领取分别显示。CodeBuddy 国内按自然日显示下一周期。

重复点击会合并进行中的领取；网络中断或响应不确定时不会自动重试，请先刷新状态核对。需要验证或资格受限时请进入官方客户端处理。国际版 CodeBuddy、国内版 Qoder、ZCode 领取本版尚未开放，DeepSeek 与 Codex 没有新增签到按钮。

本版新模块的真实只读查询已通过；实际领取仅通过模拟接口回归，未替用户执行真实领取。安装后的 DSH 宿主操作仍需验收。

## 2.1.2 入口验证与更新提醒

- 配置页常驻 Star 链接；本次启动首次进入配置页显示一次可关闭的感谢弹窗，子页面切换不重复打扰。
- CodeBuddy、Codex CLI、Qoder、ZCode 入口增加验证按钮。点击后确认发送短请求，展示实际文字回复；不会自动发送模型请求或携带聊天历史。CodeBuddy 可选择国内／国际区域，并使用该区域当前账号。
- 平台入口下方只显示额度数字或百分比；未读取用“—”，多个区域／窗口用斜线分隔。模型配置列表不展示 DeepSeek API 余额；额度页及底部摘要的 DeepSeek 余额统一保留两位小数。
- 项目协作概览和对话页直接提供“开始成员交流”“设置自动转接”。成员交流可选择顺序、人工／自动模式和次数上限；自动转接使用流程模板与角色绑定，仍需要对应权限。
- 每次 DSH 前端启动通过额度入口组件检查一次原仓库最新稳定 Release；数字版本高于本机才提示去插件市场或 GitHub 更新。未联网、限流、预发布及较旧版本不会误报，不自动下载或安装。关闭提醒后本次启动不重复弹出。

## 2.1.1 项目协作与账号池

项目协作按概览、待办、对话、成员、任务、工作流、执行记录、文件与产物、问题记录及审计分组。补充交接摘要、任务筛选和子任务、可视化流程编辑、运行记录整理、产物图片预览与下载、头像和提示词分析。完整入口见[功能对照](docs/agent-hub/功能对照.md)。

CodeBuddy 账号池逐个查询官方积分余额，支持搜索、直接设为默认账号，登录和详情折叠展示。切换默认账号用于后续会话，已有账号标记的会话不会自动改绑。支持 Windows 官方 npm/Node CLI 稳定版 2.174 以上的 2.x；新版本必须通过所需参数检查，原生 exe 和 3.x 暂不支持号池隔离。实际检查了 2.177.0 和 2.181.0 的官方版本与帮助参数；2.181.0 的真实多账号登录、令牌刷新和模型扣费尚未验收。

平台入口显示可用、部分可用、待验证、待配置、不可用或已关闭。仅找到 CLI 不算模型可用；错误详情在配置页查看。CodeBuddy 切换默认账号后不能沿用旧账号的调用成功状态。

## 2.1.0 配置页面

模型配置首页只保留 CodeBuddy、Codex、Qoder、ZCode 的图标与名称入口。各提供方共用页头、返回、额度导航与表单样式；Codex 项目模式保留在 DKN Agent 首页及 DSH 设置中，不放进模型配置首页。侧栏底部改为可点击的用量图标，全部显示开关关闭时隐藏。

额度页优先复用 DSH 登录账号服务读取 DeepSeek 充值及赠金余额。CodeBuddy 按当前 CLI 账号读取官方有效积分包；Qoder 使用官方 CLI 账号查询协议读取套餐和加量包；ZCode 查询 Coding Plan 窗口或 Start Plan 余额。失败、未登录和没有套餐分别提示，支持手动刷新。来源与边界见[余额说明](docs/compatibility/quota-sources.md)。

本版通过 67 项核心回归（1 项可选 ASAR 测试跳过）以及配置页面、项目侧栏、Qoder 界面测试。配置界面测试覆盖暗色／浅色、390px 窄窗口、四个平台导航与额度跳转；这些是本地浏览器模拟宿主测试，本轮未在已安装的 DSH 中发送模型请求。

## 基础能力

| 功能 | 当前行为 |
| --- | --- |
| Codex 整理 | 原生项目行与菜单；新建、改名、目录、排序、移除项目；对话改名、归档／恢复、项目归属、分区管理 |
| 旧对话归属 | 合并正式项目归属与未分配但目录完全匹配的历史对话；目录匹配仅用于显示，不修改归属 |
| 原生对话 | 首次导入文字、命令输出、文件变更路径；随后在 DSH 继续同一个 Codex 线程 |
| 项目模式模型 | Codex 项目会话只显示 Codex Agent 模型（取自本机模型缓存，含推理档位）；普通会话隐藏该提供方，既有会话保留回退 |
| CodeBuddy CLI | 国内／国际通道提供 DSH 模型输出，与完整 Codex Agent 分开，不做网关互转 |
| Codex CLI | 本机 CLI 模型提供方；配置页支持版本检测、真实调用测试、模型清单和运行参数 |
| ZCode CLI | 通过 ZCode 常驻 app-server 提供动态模型目录、真流式、图片输入和会话复用；账号由本机 ZCode CLI 管理 |
| 项目与成员 | 同步 DSH 工作区项目与项目内对话；配置职责、指令与权限；模型沿用原对话当前选择 |
| 通信与交接 | 指定成员、群聊与精确 @成员、单成员消息视图、人工批准交接、协助提议与审批 |
| 任务与验收 | 执行者、独立审查者、依赖、重试；执行结束与验收通过分开；人工验收记录证据 |
| 工作流 | 开发→独立审查→人工收口模板；逐步确认或自动交接、暂停、继续、停止与人工介入 |
| 并行与冲突 | 不同目录可并行；同目录及父子目录在插件协作执行中排队；不自动创建 Git worktree |
| 产物与恢复 | 项目文件只读预览、产物登记／检查、审计、备份导出与合并恢复、不确定提交人工核对 |

Hub 通过 DSH 原生 Session Controller 向已有对话发送消息，不再单独接入 Codex、Claude 等外部软件。原对话所选模型仍可来自本插件或其他提供方。详见[协作使用说明](docs/agent-hub/README.md)。

CodeBuddy 说明：[国内指南](docs/codebuddy/cn/使用与故障处理指南.md)、[国际指南](docs/codebuddy/intl/使用与故障处理指南.md)、[多账号指南](docs/codebuddy/cn/多账号使用指南.md)。

只需要 CodeBuddy 国内 CLI 的用户可以使用[独立 CodeBuddy 版](https://github.com/1924225725-collab/dsh-codebuddy-cli-cn)，安装包见[独立版 Releases](https://github.com/1924225725-collab/dsh-codebuddy-cli-cn/releases)。

ZCode CLI 的模型提供方来自 [dsh-zcode-plan-bridge](https://github.com/tangyixiao/dsh-zcode-plan-bridge)，使用前请先安装并登录本机 ZCode CLI。默认工具权限策略为拒绝，只有明确选择自动允许时才会代为响应工具授权。

## 兼容与执行边界

- 首次导入的 DSH Session 是 Codex 历史副本。之后在外部 Codex 桌面新增的消息**尚不会自动补齐到 DSH 历史**；协作页可显式同步成员历史。DSH 自身列表里的改名／归档只改变 DSH 副本，Codex 项目区菜单操作才写回 Codex；尚未实现完全双向同步。
- 导入不含推理条目、附件和完整文件差异。文件活动卡不等于提交或验收。Codex 适配器转交最新文字输入，工具和权限由 Codex 管理，不转交 DSH 工具定义或附件。
- Codex 项目／分区部分接口仍为 experimental；不支持时显示错误，不直接修改原生数据库。目录兼容查询只匹配精确项目根目录。
- 目录排队只约束本插件的协作执行。外部桌面、手动对话或编辑器仍可能同时改文件，需要并行修改时请提供独立 worktree。
- 收到回执、执行结束、验收通过是不同状态。断线／回执丢失不自动重发；先同步原生历史、人工记录实际结果，再解除阻塞。停止调度与中断原生运行是两个动作。
- 侧栏补丁会备份并修改匹配版本的 DSH app.asar。锁定时由独立辅助进程等待完全退出后校验摘要并替换，最长等待 15 分钟。未知版本／布局、目录不可写或摘要变化时停止。DSH 更新后通常需要新版插件适配。

## 本机数据

数据位于 `%LOCALAPPDATA%\dsh-dkn-agent`。`operations.json` 为不含消息正文的 Codex 去重记录，`native-threads.json` 保存 DSH 与 Codex 线程映射。

`hub` 子目录保存DSH 项目／对话的协作映射、职责、权限、协作消息、任务、审查、审计及回执，**含协作内容与本机路径**。导出备份也包含这些内容。不会自动读取或导入原 Agent Hub 用户数据。恢复是合并，同 ID 保留现有记录；导入前另存备份，新导入成员执行权限关闭，不恢复自动运行。

文件预览限制在项目内，阻止路径／符号链接越界，排除常见认证和密钥文件。本机面板写接口检查来源与请求标记。用量采用原生运行时报告，不提供统一计费；ZCode 的输入上报含缓存命中，插件按 DSH 互斥桶把缓存拆出，避免同一批 token 计两遍。

- 2026-11-10：核心回归 48 项通过、1 项跳过，覆盖 ZCode 用量归一化（缓存只计一次）与 Codex 项目模式模型清单／`model`+`effort` 透传；构建产物已核对含客户端隔离补丁。

- 使用原生 DSH 组件检查共用滚动与项目行；协作浏览器流程覆盖权限、@路由、开发／独立审查、人工收口工作流、产物和审计。

这些检查使用隔离目录与合成回复，没有调用真实模型、读取真实对话或更改已安装 DSH。真实账号下完整执行、实际桌面退出补丁周期及跨端即时刷新仍需实际试用验收；当前为基础预览版。

## Qoder ACP

2.0.3 新增 Qoder 官方 CLI 的 ACP 接入。进入“模型配置 → Qoder（ACP）”检测路径、登录状态、动态模型清单并发送真实测试。仅支持文本；每次调用创建独立会话，附带 DSH 文本历史。新的工具授权请求默认拒绝。安装与功能边界见 [Qoder ACP](docs/qoder-acp.md)。
