# DKN Workbench 使用攻略

## 安装并跑通第一条对话

在 DSH 插件市场搜索 dsh-DKN-Workbench 并安装。也可以到 GitHub 的 Releases 下载对应版本的 .tgz，再用 DSH 的本地插件安装功能导入。更新前先保存手头的对话和工作。

从 DSH 左栏打开「DKN Agent」，进入「模型与平台」，挑一个你已有账号的平台。按该平台页面完成安装和登录，再点「验证」或「发送测试」。看到模型实际返回文字后，到一个普通 DSH 新对话，选择该平台的模型，发一条短消息。

「已找到 CLI」表示程序能被检测到。ACP 握手成功表示能创建会话。「已收到真实回复」才表示这次账号和模型调用成功。某个模型验证通过后，换到另一个模型仍可能遇到额度或账号权限限制。

## 各平台怎么接入

### CodeBuddy 国内版与国际版

先切换到要用的区域。在「CLI 安装与检测」查找本机安装，缺少时使用官方安装入口。按照页面命令登录对应区域，再检测并测试。要切换账号，到账号管理或号池选中目标账号，并查看该账号的积分。两个区域的登录和积分分别计算。

### Codex CLI 与项目模式

普通会话用「Codex」配置。缺少 CLI 时点「一键部署 CLI」，或按官方安装指南手动安装。选择已有安装时也可以填写完整路径。用页面给出的登录命令完成授权，再发送测试。如果要浏览和继续本机 Codex 项目，打开独立的「Codex 项目」入口，点击连接本机 Codex。首次安装提示侧栏适配需要重启时，从托盘完全退出 DSH 后再打开。

### Qoder ACP

先部署或检测 Qoder CLI，再按 CLI 的官方登录流程授权。回到插件，先点「检测 ACP 连接」，再发送一条测试消息。每日奖励使用 Qoder 国际桌面账号，可能与 CLI 当前账号不同。对比签到状态前，先确认桌面客户端登录的是你要领奖的账号。

### Antigravity ACP

先部署或检测 agy CLI，按页面登录命令完成 Google 授权，再检测 ACP 并发送测试。连接超时时，在该平台的「连接」页检查代理地址和「使用 Windows 系统代理」开关。CLI 能运行但账号验证未通过时，查看返回的登录或账号资格提示。

### ZCode

缺少 CLI 时，点击「下载并打开安装向导」，完成官方桌面安装。回到插件点「检测 CLI」。安装到非默认目录时，填写安装目录下实际的 resources／glm／zcode.cjs 路径。这个入口需要独立 Node.js，检测不到时可在「连接」页填写 node.exe 的完整路径。

在「账号通道」选实际使用的账号。Standalone／Coding Plan 按页面命令登录，Desktop Start Plan 在 ZCode 桌面端登录。检测到 CLI 但模型列表仍没有 ZCode 时，重启一次 DSH，再发送连接测试。

### TRAE CN 与 OrcaTerm

TRAE CN 使用国内个人版桌面账号。先在 TRAE 桌面端登录，然后回插件点击「检测登录与模型」和「发送测试」。自动发现失败时，填写国内版安装位置。

OrcaTerm 在插件里点击「扫码登录」，用微信完成授权，再刷新状态并发送测试。这个接入不需要安装 CLI。当前支持文字；图片、工具调用和签到暂未开放。

## 额度、签到与后台

工作台「额度」显示上游能查到的当前余额、套餐或限额。「—」表示还没读到可显示的值。CodeBuddy 要核对区域和所选账号，Qoder 要区分 CLI 套餐与桌面奖励账号，DeepSeek 要核对显示的数据来源。侧栏额度入口可在右上角齿轮「插件总设置」中开关。

签到入口在「模型与平台」。先刷新状态，显示可领取时再点「一键签到」。自动签到需手动开启，当前计划在北京时间每天 11:00–13:00 随机执行一次，只处理已接入并启用的账号。

想在退出 DSH 后继续提供 API 或自动签到，在「后台与自动化」开启「退出 DSH 后继续运行」。想登录 Windows 后自动启动，再开启相应开关。若提示缺少独立 Node.js，按后台设置中的部署指引完成安装，再点「重新检测环境」。后台启动与 API 开始监听是两个状态。

## 在其他软件使用统一 API

在「API 服务」选择实际要调用的平台和模型，按页面提示完成验证，然后保存模型路由。生成并复制 API Key，启动服务，确认状态为运行中。Key 只在生成或更换后显示，请保存到你自己的密码管理工具。

在 WorkBuddy 等客户端选择 OpenAI 兼容方式。Base URL 填 API 页面显示的地址，默认是 http://127.0.0.1:18789/v1。填入刚复制的 Key，模型名称用对外名称，默认 dkn。之后要换模型，只需回插件改路由，再发一条消息验证。

如果只通过了「测试连接」，请再发送实际对话。遇到 HTTP 401，检查当前 Key。遇到 HTTP 413，减少历史或附件，特别是图片。遇到模型不可用，先回「API 服务」看目标模型的验证状态，再检查平台的账号、额度和网络。接口默认仅供本机使用。

## 用 DSH 项目组织协作

先在 DSH 创建或打开工作区项目，并在项目下准备需要参与的对话。打开「项目协作」，选择该项目并同步。现有对话会显示为成员，可以分别设定职责和协作权限，各成员沿用其 DSH 会话的模型。

在「对话」中选接收成员或使用 @。没有接收人时，消息只记入群聊。需要执行多步协作时，到「任务」指定执行者、验收标准和依赖，再用「工作流」安排处理顺序。先用简单任务确认消息能进入对应 DSH 会话，再启用会触发模型的流程。

## 连接问题怎么排查

找不到 CLI：先从「连接」页检测。没有安装就使用部署入口或官方安装指南。已经安装但仍找不到时，填写可执行文件或页面要求的入口路径，保存后重新检测。

连上却没有回复：确认当前账号已完成授权，换一条纯文字短消息测试。如果返回余额不足或缺少资源包，到对应平台检查权益。ACP 握手成功后仍超时，优先检查代理、地区资格和 CLI 版本。

配置页通过但 DSH 会话失败：在普通新对话选中同一个模型重试。只有旧会话失败时，再检查历史中的图片、文件或模型切换报错。不同模型提供的图片和工具能力有差异。

更新后打不开 DSH：先记录 DSH 版本、插件版本和启动错误。可用 DSH 启动错误页的「禁用第三方插件」恢复进入应用，再按日志定位具体插件。反馈时附上平台、使用入口、是否收到真实回复和去除凭据后的错误文本。
