# 本机项目协作基础版

复用原 Agent Hub `2.3.1` 的后端领域核心，不迁移 Flutter、不启动原 Hub 服务、不自动读取其用户数据。界面位于 DSH 主面板，使用 DSH 主题、按钮、菜单和弹窗。在 DSH 总设置中，DKN CodeBuddy 与 DKN Agent · Codex 各自拥有独立设置页；项目侧栏只保留工作区与 Codex 对话。

## 开始协作

1. 右键 DSH 工作区选择“项目协作”，或从 Codex 项目菜单进入。第一次登记项目目录，不自动发送模型请求。
2. 在“成员”添加执行者与独立审查者，分别绑定已有 Codex／DSH 会话或创建新会话。Claude 可新建或手动填写已有 CLI 会话 UUID。
3. 配置职责、补充指令、目录、模型、推理强度。按需分别开启发送、任务执行和成员交接权限；初始不授予这些权限。模型由对应原生运行时报告。
4. 在“对话”勾选收件人或输入精确 @成员名，再显式发送。选择成员可单独查看其消息；同步历史读取所绑定会话。各成员保留独立原生上下文，不共享桌面窗口。
5. 在“任务”填写要求、验收标准、执行者、独立审查者与前置任务。可人工推进或执行“开发与独立验收”。运行结束与验收通过分开记录，人工通过需填写证据。

同项目内不能把同一个原生会话登记为两个成员充当独立审查者；导入 DSH 的 Codex 别名与原线程也按同一身份处理。

## 交接、流程与并行

消息交接保留来源成员、原消息和关联任务。成员可返回结构化协助提议，负责人批准后才发送。限制交接深度、数量与已访问成员，防止回环，不把普通回答自动广播给所有成员。

“工作流”可建立执行→独立审查→人工收口模板，绑定角色，选择逐步确认或自动交接，支持暂停、继续、停止、人工补充要求和退回后的证据处理。另有有上限的顺序成员讨论；自动讨论需要明确选择，不因添加成员而启动。

任务可依赖顺序执行，也可批量运行独立任务。不重叠目录最多同时执行四个，同目录及父子目录排队。目录锁仅约束本插件协作运行，无法锁住外部编辑器和手动对话。需要同时修改同一仓库时，应给成员提供独立 worktree，再集成验收。

## 运行时

| 运行时 | 接入与边界 |
| --- | --- |
| Codex | 官方 app-server；独立线程、模型目录、流式输出、工具审批和中断；项目／分区接口随官方版本变化 |
| DSH | 当前 Host 的 Session Controller；不启动额外 DSH，不经过原 Hub HTTP 桥；模型与工具行为沿用 DSH |
| Claude | 官方 CLI 打印与流式 JSON；首次 session-id，之后 resume；只登记自己的会话，不读取外部私有历史或控制桌面 |
| CodeBuddy | 国内／国际 CLI 作为 DSH 模型提供方，经 DSH 成员使用；不是控制 CodeBuddy 桌面窗口 |

可选 Claude 路径在插件配置的 `claudePath` 设置，留空查找 PATH 与常见官方位置。只读使用 plan 与读取工具；写入使用 acceptEdits 和指定工具，不启用权限绕过。它不是 OS 沙箱。模型、权限参数或协议不兼容时明确报错，需适配对应版本。

官方参考：[Codex app-server](https://developers.openai.com/codex/app-server)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)、[Claude 无界面调用](https://code.claude.com/docs/en/headless)。账号登录与用量归各原生运行时管理，插件不统一计费。

## 停止、审批与恢复

Codex 审批只针对触发它的线程和回合；权限撤销或执行停止后不能继续批准。DSH 工具权限沿用 DSH 自身流程。

停止后续调度与中断原生执行是两个动作。停止不宣称已经杀死外部工具；中断后仍应检查原生结果。插件关闭或断连不代表外部 Agent 已停止。

每次提交使用持久操作编号。回执丢失先查询同一编号，不另建编号重发。重启后的待执行记录变为中断或待核对，不重放模型请求。结果不确定的会话阻止后续发送，需先同步原生历史，记录实际观察结果，再解除阻塞。

“审计与恢复”可导出本插件协作快照、合并导入备份。同 ID 保留现有记录，导入前另存于 `hub/backups`；新导入成员执行权限关闭，流程不自动恢复。备份含消息正文、本机路径和证据，应按项目资料保存。

## 文件与产物

只读列出项目文件、预览文本、登记产物并检查存在性，可关联任务和消息。限制在项目目录内，拒绝符号链接越界与常见认证、密钥文件。登记和存在性检查不等于内容验收。

## 来源与验证

`vendor/agent-hub` 保留原 Hub 的项目／成员、任务状态机、工作流、审查报告、消息路由、审计和快照恢复；`lib/hub` 提供 DSH 内嵌接入、原生适配、目录排队与持久回执。构建转换选定 TypeScript，不分发旧 Flutter、Tauri、独立服务或安装器。MIT 许可见 [LICENSE](LICENSE)。

去重、丢失回执、重启恢复、交接边界、目录冲突和浏览器流程已通过合成数据验证。尚未调用真实模型或在真实登录状态下验收完整任务，因此属于基础预览版，不代表所有运行时版本与桌面行为已验证。
